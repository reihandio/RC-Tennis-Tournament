# Tennis Match Generator Rules

## Match Logic & Standings (Social Doubles)
- Players register as INDIVIDUALS (e.g., Cynthia, Rei, Alex, Jordan).
- In Doubles Mode:
  - DO NOT create fixed "Teams".
  - Matches are generated by rotating 4 players per match into two pairs (e.g., "Cynthia & Alex" vs "Rei & Jordan").
  - Matches must be randomized so every individual plays roughly equal total matches and partners with different players.
- Standings Table:
  - Table columns: Pos | Player | Played (P) | Win (W) | Lose (L) | Win %
  - Standings track INDIVIDUAL player statistics.
  - When Team (A & B) beats Team (C & D), both Player A and Player B get +1 Win. Players C and D get +1 Loss.

# Fixed vs. Randomized Doubles Standings Rules

## Standings Behavior
- **Fixed Teammates Mode:**
  - Standings table column header: **Team / Pair** (e.g., "Alcaraz & Nadal").
  - Matches are played team vs. team.
  - Wins, losses, and win percentages are tied directly to the **fixed couple** as a single entity on the leaderboard.
- **Randomized Teammates Mode:**
  - Standings table column header: **Player** (e.g., "Alcaraz").
  - Matches shuffle partners every round.
  - Wins, losses, and win percentages are tracked for **individual players**.

# Multi-Court Scheduling & Conflict-Free Generation Rules

## Scope
- Applies to BOTH **Singles** and **Doubles** (Randomized & Fixed Teammates) match generation.
- Match generation produces a **round-based schedule**: matches in the same round are played simultaneously, each on a different court.

## Court Selection
- Provide a **"Number of Courts"** selector in the generator panel (segmented control / stepper): **1, 2, 3, or 4**. Hard maximum is **4**; reject or clamp any value outside 1–4. Default: **1**.
- Courts are labeled **Court 1 … Court N** and shown on every match card as a pill/badge.
- Persist the selected value as `courtCount` in app state (see Persistence rules).

## Round Structure
- Total matches = the existing `matchCount` input (e.g. "Generate 6 Matches").
- Rounds = `ceil(matchCount / courtCount)`. Each round holds up to `courtCount` matches, one per court. The last round may hold fewer matches if `matchCount` is not divisible by `courtCount`.
- Every match stores `round` (1-based) and `court` (1–4) in addition to existing fields.

## Hard Constraint: No Player Clashes
- Within a single round, **a player (or fixed pair, in Fixed Teammates Mode) MUST appear in at most ONE match.** A person can never be scheduled on two courts at the same time.
- Required players per match: **Singles = 2**, **Doubles = 4** (Fixed Teammates = 2 pairs).
- **Effective court count:** `effectiveCourts = min(courtCount, floor(totalPlayers / playersPerMatch))`.
  - If `effectiveCourts < courtCount`, automatically reduce courts for generation AND show a friendly inline notice (e.g., "Only 2 courts can be used with 8 doubles players").
  - If `effectiveCourts < 1` (not enough players), block generation with a clear validation message.

## Rest / Bye Handling
- If registered players exceed `effectiveCourts * playersPerMatch`, the remaining players **rest** (bye) that round.
- Show a **"Resting: Name, Name"** chip under each round header.
- Rest assignments must rotate fairly: players with the fewest matches played so far (or the most recent rests) get priority to play next.

## Generation Algorithm (per round)
1. Track running counters per player: `matchesPlayed`, `restCount`, partner history (doubles), opponent history.
2. Build each round by selecting players for play, prioritizing lowest `matchesPlayed`, with random tie-breaking.
3. For Doubles (Randomized): split selected players into pairs minimizing repeated partners, then minimizing repeated opponents.
4. For Fixed Teammates: treat each pair as a single unit; units cannot repeat within a round, and the same match-up should be avoided until all match-ups have been used.
5. Avoid repeating the same full match-up (identical pairings) in the same schedule when alternatives exist.
6. If a round cannot satisfy preferences, relax soft rules (partner/opponent variety) — **never relax the no-clash hard constraint**.
7. After generation, run a **schedule validator** that asserts no player appears twice in any round; if it fails, regenerate (max retries, then show an error).
8. Overall distribution goal: every player's total matches differ by **at most 1**.

## Schedule UI
- Display matches **grouped by round**: a "Round N" header, then that round's match cards laid out per court (grid on desktop, stacked on mobile).
- Each match card keeps vertical name stacking (Team 1 on top, Team 2 below) and shows the **Court badge**.
- "Generate Matches" regenerates the whole schedule (with confirmation if scores have already been entered).
- Optional helper: **"Regenerate Round"** to reshuffle only a single unplayed round without breaking the no-clash rule.

## Manual Editing Interaction
- Manual editor and "Add Custom Fixture" must include **Round** and **Court** fields.
- Real-time conflict validation on save:
  - Block saving if any selected player already appears in another match in the same round (show which player and which match).
  - Block saving if the same Court is already used in the same round.
- Deleting a match leaves its round intact (the court slot becomes empty); empty rounds are removed automatically.
- Standings recalculation is unaffected by round/court (they only affect scheduling).

## Backward Compatibility
- On import/load, matches missing `round` / `court` get defaults (each match placed sequentially: `round = index + 1`, `court = 1`) and `courtCount` defaults to 1.

# Tournament State Persistence Rules

## Save State & Import/Export Features
- **Auto-Save (LocalStorage):** Sync application state (`players`, `matches`, `matchType`, `template`, `clubLogo`, `matchCount`, `courtCount`) to `localStorage` key `tennis_app_state`. Each match object includes `round` and `court`.
- **JSON Export:** Provide a "Save State" / "Export Tournament" button that downloads the full current app state as a timestamped JSON file (e.g., `tennis-tournament-2026-07-30.json`).
- **JSON Import:** Provide a "Load State" / "Import Tournament" file uploader that restores state from a previously exported JSON file.
- **Reset Button:** Include a "Reset Tournament" action (with a confirmation modal or prompt) to clear state and start fresh.

# Exportable Image Customization Rules

## Standings Poster Customization
- **Editable Title:** Provide a text input field so the user can customize the main tournament title (defaults to the selected template name, e.g., "Wimbledon", "Roland Garros", or "US Open").
- **Date Display:** Automatically display today's date (formatted nicely, e.g., "July 30, 2026") below the title inside the export container.

# Export Canvas Mobile Layout Rules

## Export Container Formatting (`html-to-image`)
- **Fixed Width Canvas:** The DOM container attached to `exportRef` MUST have a fixed minimum pixel width (e.g., `w-[600px]` or `min-w-[600px]`) during render/export.
- **Table Cell Formatting:**
  - Use `table-fixed` layout with explicit column widths (e.g., Pos: 10%, Name: 45%, P/W/L: 10% each, Win%: 15%).
  - Ensure text wrapping/truncation rules (`truncate` or `whitespace-nowrap`) are explicitly set on table cells to prevent awkward line breaks on mobile viewports.

# Match Editing & Overrides Rules

## Manual Match Editor & Save State
- **Editable Match Fields:**
  - *Singles Mode:* Player 1, Player 2, Score 1, Score 2, Round, Court.
  - *Doubles Mode (Randomized & Fixed):* Team/Pair 1 (Player A & Player B), Team/Pair 2 (Player C & Player D), Score 1, Score 2, Round, Court.
- **Match Management Actions:**
  - Allow adding a manual custom match (e.g., "Add Custom Fixture").
  - Allow deleting an unwanted generated match.
  - Provide a "Save / Update Match" button that recalculates standings in real-time upon saving.
- **Persistence:** Save all manually edited/added matches inside `localStorage` and the downloadable JSON export.

# Standings Table & Export Column Customization Rules

## Custom Standings Columns
- **Default Core Columns:** `Pos | Player/Team | P | W | L | Win %`
- **Active Additional Columns:**
  - **Game Difference (+/- or GD):** Track total net game difference (Total Games Won minus Total Games Lost) as the primary tiebreaker metric. *(Note: GW and GL are excluded to keep the layout minimal).*
  - **Points (PTS):** Total points accumulated (e.g., +2 pts per match win).
- **Final Column Layout:** `# | PLAYER / TEAM | P | W | L | +/- | WIN% | PTS`
- **Export Consistency:** The Grand Slam export container (`ref={exportRef}`) MUST strictly mirror this clean 8-column layout with fixed column width distributions (`table-fixed`) so headers and cells align seamlessly in the exported PNG poster image across all devices.
